# Публикация серверной версии через GitHub и Cloudflare

Автономная версия без сервера публикуется непосредственно на **GitHub Pages**: https://kgruzdova.github.io/stafftrack/. Её данные хранятся в браузере; настройка описана в [GITHUB-PAGES.md](GITHUB-PAGES.md). Ниже описан отдельный вариант для совместной работы команды с общей базой данных.

GitHub хранит исходники и запускает сборку и публикацию через GitHub Actions. Рабочий сайт обслуживает Cloudflare Workers; данные хранятся в D1, вложения — в R2. GitHub Pages поддерживает статические страницы и не запускает серверный API этого приложения.

## Однократное подключение

1. Создайте аккаунт [Cloudflare](https://dash.cloudflare.com/) и включите Workers и R2. Для R2 платформа может запросить платёжный способ; проверьте условия и лимиты своего аккаунта.
2. Найдите **Account ID** в панели Cloudflare.
3. Создайте API token для выбранного аккаунта с правами **Workers Scripts: Edit**, **Workers R2 Storage: Edit**, **D1: Edit**, **Account Settings: Read**. Для публикации на `workers.dev` доступ к DNS не требуется. Ограничьте токен своим аккаунтом.
4. В репозитории GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**. Добавьте:
   - `CLOUDFLARE_ACCOUNT_ID` — идентификатор аккаунта;
   - `CLOUDFLARE_API_TOKEN` — API token.
5. Откройте **Actions → Publish StaffTrack → Run workflow** и выберите ветку `main`.
6. После успешной публикации ссылка на сайт появится в итогах запуска и в журнале шага публикации.

Не добавляйте токен в исходники и не отправляйте его в чат. GitHub Secrets передаёт его только процессу публикации.

## Что происходит при публикации

- Устанавливаются зависимости из lock-файла, проверяется TypeScript, собираются клиент и сервер.
- Создаются или повторно используются база `stafftrack-db` и хранилище `stafftrack-files`.
- Применяются только ещё не выполненные SQL-миграции из `drizzle`.
- Worker `stafftrack` публикуется на адресе `https://stafftrack.<ваш-поддомен>.workers.dev`.
- Последующие изменения в `main` автоматически обновляют сайт. Данные сохраняются между публикациями.

Имя приложения можно изменить до первой публикации через переменную GitHub Actions `WORKER_NAME`, например `stafftrack-team`. Изменение имени также меняет имена базы и хранилища и создаёт отдельное окружение.

Если Secrets ещё не добавлены, workflow проверяет и собирает проект, сохраняет сборку как artifact и сообщает, что сайт **не опубликован**.

## Данные и доступ

Публикация в вашем аккаунте Cloudflare создаёт новый сайт с отдельной базой. Данные существующего сайта Sites и локальная база автоматически не переносятся. После первой публикации создайте компанию на странице входа.

Адрес `workers.dev` доступен из интернета; рабочие данные защищены входом в StaffTrack и проверками ролей. Ограничение аудитории существующего сайта Sites на новый адрес не переносится. Если требуется закрыть даже страницу входа, настройте Cloudflare Access перед приглашением команды.

Почтовый сервис восстановления пароля подключается отдельно через секреты Worker `MAIL_API_URL`, `MAIL_API_KEY`, `MAIL_FROM`. Подробнее в [технической документации](DEVELOPMENT.md).

Основа процесса: [официальная инструкция Cloudflare для GitHub Actions](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/).
