# Автономный StaffTrack на GitHub Pages

Адрес: https://kgruzdova.github.io/stafftrack/

Эта версия работает без сервера и аккаунта Cloudflare. При первом открытии нажмите **«Создать компанию»**, задайте имя, email и пароль. Можно добавить демонстрационную команду и задачи. Ранее созданные аккаунты и данные серверного сайта сюда не переносятся.

Сохраняются задачи, несколько исполнителей, приоритеты, статусы, комментарии, история, вложения до 10 МБ, сотрудники, баллы, награды и настройки. Данные и локальная сессия лежат в IndexedDB этого браузера. Перезагрузка страницы сохраняет данные; очистка данных сайта удаляет их. Другой браузер, профиль или устройство открывает отдельную пустую базу. Аккаунты сотрудников предназначены для переключения ролей на этом устройстве, а не для совместной работы с разных компьютеров.

Восстановление пароля через email недоступно: сервер почты отсутствует. Администратор может изменить пароль сотрудника в разделе «Сотрудники». Не используйте эту локальную версию как средство защиты данных от других людей, имеющих доступ к тому же профилю браузера.

## Автоматическая публикация

В **Settings → Pages → Build and deployment → Source** выбран **GitHub Actions**. Workflow **Publish GitHub Pages** (`.github/workflows/pages.yml`) проверяет типы и сценарии задач, собирает статический сайт и публикует его при изменении `main`. Можно запустить публикацию вручную через **Actions → Publish GitHub Pages → Run workflow**. Секреты для GitHub Pages не нужны.

Сборка использует базовый путь из `actions/configure-pages`. Для локальной проверки:

```sh
npm ci
npm run test:pages
npm run build:pages
npx vite --config vite.pages.config.ts --host 127.0.0.1 --port 5174
```

Откройте http://127.0.0.1:5174/stafftrack/.

## Устройство автономной версии

Интерфейс общий с серверным приложением. `pages/browser-api.ts` выполняет существующий обработчик `lib/server.ts` внутри браузера; SQLite работает через WebAssembly (`sql.js`). `pages/d1-adapter.ts` поддерживает используемые операции D1 и атомарные SQL batch. Схема берётся из неизменённых миграций `drizzle/*.sql`, новые миграции применяются по журналу `_browser_migrations`.

После изменений SQLite экспортируется в IndexedDB вместе с локальной сессией; файлы сохраняются как Blob. Обновление базы и файлов происходит в одной транзакции IndexedDB. Вкладки используют Web Locks и проверку ревизии, чтобы не затирать изменения друг друга. Сохранение подтверждается только после успешной записи. Вложения открываются через локальные Blob URL после проверки доступа к задаче. Данные пользователя не отправляются на сервер.

Серверная сборка, сайт Sites и workflow Cloudflare остаются отдельными вариантами. Их настройки описаны в [DEPLOYMENT.md](DEPLOYMENT.md).
