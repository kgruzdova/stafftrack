# StaffTrack

Адаптивная платформа задач и мотивации персонала по `tz.txt`. Реализован полный сценарий приёмки MVP из раздела 37, а также каталог наград, заявки на награды и бонусы.

## Быстрый запуск в Windows

В папке `stafftrack` запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Потребуется Node.js 22.13 или новее. Скрипт установит зависимости при необходимости, подготовит сборку и локальную базу. Откройте адрес, который покажет сервер (обычно http://127.0.0.1:5173). Остановка — Ctrl+C.

На странице входа нажмите «Создать компанию». Первый пользователь становится администратором. Флажок «Добавить демонстрационные задачи и команду» позволяет познакомиться с приложением на примере. Снимите его для пустой рабочей компании. Демонстрационные сотрудники получают технические email; замените их на реальные адреса и задайте отдельные пароли через редактор сотрудника перед использованием.

Для текущей локальной демонстрации создан аккаунт `preview@stafftrack.local` с паролем `StaffTrack2026!`. Этот аккаунт существует только в локальной базе и не переносится при публикации. В опубликованном приложении создайте собственную компанию и пользователей.

Обычные команды:

```sh
npm ci
npm run build
node scripts/init-local.mjs
npm run dev
```

`npm start` запускает собранную версию через локальный Cloudflare Worker. Для первичного запуска используйте `start.ps1`. `init-local.mjs` предназначен для первоначальной схемы и не перезаписывает существующие данные; новые миграции на существующей локальной базе применяются по порядку отдельно.

## Возможности

- Три роли: администратор управляет компанией и пользователями; руководитель создаёт задачи, проверяет работу и выдаёт бонусы; сотрудник работает со своими задачами.
- Дашборд руководителя и сотрудника, статистика загрузки, задач на сегодня, проверки и просрочек.
- Создание и редактирование задач с описанием, несколькими исполнителями, сроком до минуты, четырьмя приоритетами и баллами каждому исполнителю. Общий статус задачи изменяет любой назначенный сотрудник. Выполненные задачи также редактируются; смена состава исполнителей возвращает их в работу без отмены прежних начислений.
- Список и доска задач; поиск, фильтры по исполнителю, подразделению, статусу, приоритету и сроку.
- Цикл «Новая → В работе → На проверке → Выполнена» и возврат на доработку с обязательной причиной. Руководитель и администратор также могут напрямую выбрать любой из четырёх статусов и вернуть выполненную задачу в работу. Просрочка вычисляется автоматически по сроку.
- Удаление задач руководителем и администратором с подтверждением. Сервер устанавливает `deleted_at`: задача скрывается из списков, доски, аналитики и подсчёта выполненных задач в рейтинге; карточка и файлы закрываются для чтения. Связанные записи и история начислений сохраняются в базе, баллы не списываются, рейтинг по заработанным баллам сохраняется. Интерфейс восстановления не предусмотрен.
- Комментарии, хронологическая история действий и файлы до 10 МБ: JPG, PNG, WebP, PDF, DOC, DOCX, TXT. Содержимое бинарных файлов проверяется по сигнатуре; файлы скачиваются с проверкой доступа.
- Баллы начисляются только после подтверждения или выбора руководителем статуса «Выполнена». Уникальная ссылка `task_id:user_id` и атомарный пакет SQL предотвращают двойное начисление тому же исполнителю после возврата задачи в работу, изменения порядка исполнителей и повторного принятия. Старые ссылки `task_id` также учитываются. Изменение баллов после возврата задачи в работу не пересчитывает предыдущие начисления; впервые добавленные исполнители получают баллы при принятии результата.
- Бонусы с обязательной причиной, история начислений и списаний, рейтинг по положительным начислениям за неделю, месяц или всё время. Обмен наград не уменьшает заработанный рейтинг.
- Каталог наград, лимит количества, заявка сотрудника, резерв баллов и награды, подтверждение или отклонение руководителем. Списание выполняется только при подтверждении.
- Внутренние уведомления о новых задачах, проверке, доработке, подтверждении, бонусах, наградах и сроках. Обновление каждые 30 секунд, пока приложение открыто. Просрочка определяется по времени сервера при каждом чтении; напоминания фиксируются при обращении к приложению, а не отдельным фоновым планировщиком.
- Управление пользователями: создание, редактирование, смена роли, блокировка, сброс пароля администратором. Удаление разрешено только без истории; иначе блокировка сохраняет связанные данные.
- Профиль сотрудника с текущими и завершёнными задачами, баллами, рейтингом и историей. Должность и подразделение редактируются вместе с пользователем.
- Настройки компании: название, использование баллов, видимость рейтинга и каталога.
- Адаптивная навигация, поддержка клавиатуры, доступные диалоги. WebMCP предоставляет чтение задач и открытие карточки с действующими серверными правами.

## Архитектура и хранение

React 19 + TypeScript, Vinext / Vite, REST API в серверных маршрутах. Постоянное хранилище: Cloudflare D1 (SQLite); вложения: R2. Схема — `db/schema.ts`, миграции — `drizzle/`. При публикации Sites создаёт ресурсы и применяет миграции. Локальные данные находятся в `.wrangler/state` и исключены из репозитория и архива публикации.

Пароли хешируются PBKDF2-SHA256 со случайной солью и 100 000 итераций. Сессии: непрозрачные случайные токены, в базе хранится SHA-256; cookie HttpOnly и SameSite=Lax, Secure при HTTPS. Проверки ролей, принадлежности задачи и компании выполняются на сервере. При блокировке и изменении роли старые сессии отзываются. Неудачные входы ограничены. Изменяющие запросы с чужого Origin отклоняются.

Опубликованная первая версия имеет закрытый доступ на уровне Sites. Чтобы дать доступ другим сотрудникам, требуется настроить аудиторию сайта в Sites; пользовательские роли внутри StaffTrack сохраняются. HTTPS предоставляется платформой. Собственный домен, корпоративный почтовый сервис, внешние интеграции и автоматическое резервное копирование под конкретную политику компании требуют отдельной настройки инфраструктуры. VPS/Docker и PostgreSQL здесь не используются: ТЗ допускает выбор технологии разработчиком.

Для резервной копии локальной версии остановите сервер и скопируйте `.wrangler/state` в защищённое место. База содержит хеши паролей и персональные данные. Для опубликованной версии используйте экспорт D1 и резервирование объектов R2 на платформе.

## Восстановление пароля

Форма и одноразовые токены восстановления реализованы. Для реальной отправки писем настройте серверные переменные `MAIL_API_URL`, `MAIL_API_KEY`, `MAIL_FROM` в окружении Sites. Поддерживается HTTP API с Bearer-ключом и JSON `{from,to:[email],subject,text}` (например, API отправки писем Resend). Без настроенного сервиса форма честно сообщает, что следует обратиться к администратору; письма не имитируются. Ссылка действует один час, после смены пароля сессии отзываются. Для локального Worker можно добавить эти значения в `.dev.vars`; этот файл нельзя коммитить.

## Проверка

```sh
node node_modules/typescript/bin/tsc --noEmit
npm run build
node tests/acceptance.mjs
node tests/task-editing.mjs
node tests/task-lifecycle.mjs
```

Сервер должен быть запущен. При другом адресе задайте `TEST_URL`. Проверка создаёт изолированные тестовые компании в локальной базе. Она проверяет регистрацию, вход, три роли, изоляцию организаций, создание и выполнение задачи, доработку, комментарии, загрузку файла и отклонение неверного типа, конкурентное подтверждение без двойных баллов, бонусы, рейтинг, заявки и списание наград, просрочки, уведомления, блокировку и выход. Не запускайте её против рабочей базы с реальными сотрудниками.

## Границы первой версии

Не включены функции второй версии: повторяющиеся задачи, шаблоны, чек-листы, Telegram, email-напоминания, графики смен, достижения, уровни и сложные KPI. Аналитика показывает базовые результаты команды и сотрудников. Логотипы, аватары и фотографии наград заменены фирменным знаком, инициалами и значками. Почта восстановления требует описанной выше настройки.

Основные API: `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/state`, `/api/users`, `/api/tasks`, `/api/tasks/{id}`, `/api/tasks/{id}/status`, `/api/tasks/{id}/approve`, `/api/tasks/{id}/reject`, `/api/tasks/{id}/comments`, `/api/tasks/{id}/attachments`, `/api/files/{id}`, `/api/points`, `/api/points/bonus`, `/api/rating?period=week|month|all`, `/api/rewards`, `/api/rewards/{id}/claim`, `/api/claims/{id}/approve`, `/api/claims/{id}/reject`, `/api/notifications`, `/api/profile`, `/api/settings`.
